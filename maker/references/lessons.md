# 교훈과 위험 패턴 (지난 실패에서)

작업마다 아래 표를 하나씩 확인한다. "해당 없음"도 이유를 한 줄 남긴다.

## 공식 기능을 두고 자체 구현한 곳 (다시 하기 쉬움)

- 명령 이름을 짐작: 좀보이드 추방은 공식 `kickuser`인데 `kick`으로 선언 → 추방이 동작하지 않음. 명령 템플릿은 공식 목록과 한 줄씩 대조한다.
- 콘솔에서 필수인 인자를 선택으로 둠(좀보이드 `createhorde` 사용자명).
- 백업 일관성을 "저장 + 3초"로 대신: 마인크래프트 공식 절차는 `save-off` → `save-all flush` → 복사 → `save-on`.
- 콘솔 영문 출력 파싱·폴링: 공식 관리 프로토콜·Query·REST `/players`가 있으면 그쪽.
- 공식 실행 스크립트를 정규식으로 재해석하고 실패하면 하드코딩 classpath로 대체(좀보이드). 공식 실행 정보를 그대로 쓴다.
- 공식 인자 표기와 다름(`--port` 대 `-port=`), 외부 포트 설정에 리슨 포트를 씀(팰월드 PublicPort).
- 강제 정지에 공식 API(REST `/stop`)를 먼저 쓰지 않고 taskkill.
- 설치된 버전·실제 적용 설정을 공식 API(`/info`, `/settings`)로 확인할 수 있는데 하지 않음.
- 내려받는 파일의 공식 체크섬을 일부만 확인(서버 jar는 하고 JRE는 안 함). 받는 모든 바이너리를 같은 수준으로.
- 동의·불리언을 정규식으로 판정(`#eula=true` 주석을 동의로 봄). 키=값 파싱.

## 안전·효율 경로를 고르지 않은 곳

- 기본값을 코드 dict·toml·샘플 파일 세 곳에 따로 둠 → 서로 다르고 공식과도 다름. 게임이 만든 파일 하나를 원본으로.
- 읽기 실패를 "빈 설정"으로 보고 기본값·바뀐 키만 덮어씀 → 사용자 설정 소실.
- 사바쨩 설정 사본(level_name)으로 월드 위치를 정함 → 사용자가 파일을 고치면 백업·초기화가 엉뚱한 폴더.
- 데몬이 주는 `log_lines`를 버리고 로그 파일 위치를 짐작(다른 서버·클라이언트 로그를 진단).
- 아무 옵션·값을 받는 콘솔 setter(`changeoption`)로 시작 때 강제한 보안 정책(RCON 끔)과 단일 설정원을 우회.
- 관리자 비밀번호를 매 실행 명령줄에 실음.
- 실행 중 인증·포트 설정을 바꿔 다음 정지가 401·연결 실패 → 저장 없는 강제 종료로 몰림.
- 공식 종료가 이미 저장하는데 `save` + 고정 sleep을 덧붙이고, 데몬 경로와 모듈 경로의 절차가 달라짐.
- 예전 인스턴스가 공용 홈 폴더와 기본 이름으로 되돌아가 인스턴스 사이 격리가 깨짐.

## 모듈 간 불일치가 버그를 숨긴다

모듈 중 하나만 다르게 하면 그 모듈에서만 사고가 난다(좀보이드만 접속자·준비·정상 종료 패턴이 없었고, 초기화 뜻이 셋 다 달랐다).
새 기능·수정 전에 아래 작업마다 다른 모듈의 구현을 열어 같은 방식인지 본다: 정지·저장, 백업 전 저장, 초기화 범위, 접속자, 준비·종료 패턴,
기본값 출처, 설정 파일 문법, 이름·경로 검증, 로그 진단, 설치된 버전, 내려받기 검증. 다르게 해야 하면 이유를 조사 표에 남긴다.
