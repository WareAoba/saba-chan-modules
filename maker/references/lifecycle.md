# lifecycle.py 쓰기

함수마다 테스트를 먼저 쓰고 실패를 확인한 뒤 구현한다(testing.md). 공용 도우미 표는 `docs/module-development-guide.md` §5.

## 공통

- 진입점은 `run_lifecycle(FUNCTIONS)`(공용 `daemon_rcon`). 만든 함수는 모두 `FUNCTIONS`에 넣는다. 훅·queries·status가 가리키는 함수도. 예약 함수 `functions`가 FUNCTIONS 키 목록을 돌려준다.
- 필수는 `get_launch_command` 하나. `program`, `args`, `working_dir`, `env_vars`; `extra_args`를 알맞은 자리에 넣었으면 `extra_args_placed: true`; `preview: true`이면 파일을 쓰지 않는다. 실행 파일이 없으면 `action_required: "executable_not_found"`.
- 값은 `config_value(config, key, default)`로 읽는다(빈 값은 없는 값). `config.get(key, default)`는 빈 문자열을 그대로 돌려주므로 이름·경로 값에 쓰지 않는다. 상태를 메모리에 두지 않는다.
- 경로는 데몬이 준 `server_executable`·`working_dir`을 쓴다. 같은 경로를 함수마다 다르게 계산하지 않고 한 함수로 모은다.
- 데몬이 이미 주는 값을 쓴다: `pid`, `log_lines`(로그 진단), `players_detail`, `rest_*`. 파일 위치를 짐작해 대신하지 않는다.
- 모든 실패는 종료 코드 0 + `{"success": false, "message": ...}`. 로그는 stderr로만, 진행률은 stderr `PROGRESS:{json}`. 실패를 삼키고 `success: true`로 답하지 않는다.
- `validate`: `issues[]`의 `severity: critical`이 시작을 막는다.
- 서버 로컬 REST·소켓은 `daemon_rcon.loopback_http`/`loopback_exchange`로 연다(격리 실행에서도 데몬이 중계).
- 인스턴스 REST(저장·정지 등)는 `daemon_rcon.daemon_rest`로 보낸다. 격리 실행에서도 데몬이 그 인스턴스 서버의 REST 포트로만 대신 보낸다. 콘솔 `daemon_stdin_command`는 격리 실행에서 `op_not_allowed`다(saba-chan 0.1.11부터. 그 전 데몬은 격리 실행에서 둘 다 막는다).
- 익스텐션은 함수 안에서 `import extensions.<id>`, 없으면 `error_code: "extension_required"`, `missing_extensions[]`. PATH의 도구로 대신 실행하지 않는다.
- 비밀값(관리자 비밀번호 등)을 실행 인자에 매번 싣지 않는다. 첫 생성에만 필요한 플래그는 그때만 붙인다.
- 화면 문구·오류는 `I18n(MODULE_DIR).t(...)`, 키는 `locales/en.json`이 기준이고 ko를 반드시 채운다(10개 언어). `check.py` locales가 ko 누락을 잡는다.
- 공용 `PathOutside`는 `ValueError`의 하위 클래스다. `except ValueError`가 경로 경계 위반까지 삼켜 "잘못된 이름" 같은 일반 실패로 바꾸지 않게, 그 앞에 `except PathOutside: raise`를 둔다(데몬이 경계 위반을 따로 다룬다).
- **실행 전제는 고정 판 포터블로.** 런타임(Java, XNA, VC++ 등)은 PC에 이미 있어도 쓰지 않는다. 설치 때 공식 배포물에서 버전을 고정한 파일을 받아 서버 폴더(또는 인스턴스 폴더)에 두고 그 경로로 실행한다. 받은 파일은 공식 체크섬, 없으면 서명을 확인한 파일의 고정 SHA-256으로 검증한다. 관리자 권한·시스템 설치·서비스를 쓰지 않는다. `validate`는 그 파일이 없으면 `severity: critical`과 전용 `code`로 막고 다시 설치하라고 안내한다.
- **격리 실행에서 안 되는 것.** 확인 안 된 모듈은 AppContainer로 돈다. Windows Installer(`msiexec`, 1601), 다른 서비스, `tempfile.mkdtemp`이 만든 폴더(Python 3.13+는 현재 사용자만 쓰는 권한을 붙여 격리 계정이 못 쓴다)는 쓸 수 없다. 임시 파일은 `mkstemp`이나 직접 만든 폴더로 만든다. 설치 파일 형식(MSI·CAB 등)은 필요하면 직접 읽는다.

## 설정 (앱에서 고친 값 = 서버가 기대하는 값)

- `[[settings.fields]]` 이름 ↔ 게임 파일 키를 **표 하나**로 잇고 `configure`/`import_settings`/`read_properties`가 같이 쓴다.
- **그 형식의 공식 문법으로 읽고 쓴다.** 예: Java `.properties`는 `\:`·`\=` 이스케이프와 줄 끝 `\` 이어짐이 있다. 단순 `split("=")` 파서는 왕복할 때 값을 망가뜨린다. 인코딩·줄바꿈·키 대소문자·불리언 표기(`true`/`True`/`1`)·숫자 형식·따옴표·목록 구분자는 공식 기본 파일의 표기를 따른다.
- **인코딩을 가정하지 않는다.** 동봉 기본 파일의 실제 인코딩(`inspect_dist.py`)으로 읽고, 읽은 인코딩·줄바꿈 그대로 다시 쓴다. UTF-8로만 읽으면 레거시 코드페이지 파일(테라리아 Windows `serverconfig.txt`는 cp1252, 주석에 0x92)에서 시작·설정 저장·가져오기가 모두 실패한다. 테스트에는 공식 파일의 원래 바이트를 쓴다.
- 파일의 다른 키·주석·순서는 그대로 두고 바뀐 키만 고친다. 실행 전용 설정(JVM 인자 등)은 게임 파일에 쓰지 않는다.
- **파일 없음 / 읽기 실패 / 파싱 실패를 구별한다.** 못 읽었으면 쓰지 않는다. 빈 dict에 바뀐 키만 넣어 저장하면 나머지 설정이 사라진다.
- 기본값의 출처는 하나: 게임이 설치·첫 실행 때 만든 기본 파일, 없으면 배포물에 동봉된 예시 파일. 코드 dict·toml default·동봉 샘플에 따로 적으면 반드시 어긋난다. 코드 dict는 그 파일이 없을 때만 쓰고, toml default와 같은지 테스트로 묶는다.
- 서버가 시작할 때만 읽는 값(관리 비밀번호, REST 포트)은 실행 중에 바꾸면 관리 경로가 끊긴다. 재시작이 필요하다고 알리거나 시작 때 값을 따로 둔다.
- 파일 값은 `load_setting_types` + `coerce_setting`으로 화면 형식에 맞춰 읽는다.
- 왕복 테스트를 쓴다: 모든 설정에 대해 `configure`로 쓴 파일을 `import_settings`로 읽으면 같은 값이 나와야 하고, 쓴 파일이 공식 기본 파일과 같은 표기여야 한다. 특수 문자(`:`, `=`, `\`, 한글, 따옴표)를 넣은 값도 넣는다. 마지막에 실서버가 그 값을 실제로 적용했는지 실측한다.

## 기존 세이브·설정 참조

- 이미 서버 파일이 있는 폴더(가져오기, 재설치, 업데이트)에서는 **기존 설정과 세이브를 먼저 읽고** 그 값을 쓴다. 기본값으로 덮어쓰지 않는다.
- 월드·플러그인 위치는 게임 설정 파일과 실행 인자에서 계산한다(예: server.properties `level-name`, Paper `--world-container`). 사바쨩 설정의 사본만 보면 사용자가 파일을 고친 순간 백업·초기화가 다른 폴더를 본다.
- `import_settings`는 게임 파일의 설정을 돌려주고, 찾은 서버 실행 파일을 `executable_path`로 준다. `dir_signatures`로 기존 서버 폴더를 알아보게 한다.
- `install_server`·`reset_properties`는 기존 월드·플레이어·권한 파일을 지우지 않는다. 기본값으로 되돌릴 때도 인스턴스 고유 값(포트, 관리 비밀번호)은 다시 적용한다.

## 백업: 최소 용량, 일관된 스냅샷

- 서버 폴더 전체 복사는 원칙적으로 금지. 데이터를 살리는 데 꼭 필요한 최소 구성만 고른다: 월드 세이브, 플레이어 데이터, 권한(op·화이트리스트·밴), 서버 설정 파일, 플러그인·모드 데이터.
- 빼는 것: 서버 실행 파일·라이브러리(다시 설치 가능), 로그, 캐시, 크래시 덤프, **게임이 스스로 만든 백업 폴더**, 다른 서버 이름의 세이브.
- 폴더 안에 뺄 것이 섞여 있으면 폴더째 넣지 말고 `[backup] hook = true` + `backup_paths`가 필요한 파일·하위 폴더만 돌려준다(`paths`는 파일도 받는다). 활성 월드 이름처럼 설정에 따라 달라지는 경로도 hook에서 계산한다.
- 백업 전에 `save_command`로 디스크에 쓰게 한다. 게임에 공식 쓰기 중지·즉시 기록 절차가 있으면 그것이 기준이다. "저장 명령 + 몇 초 대기"로 대신하지 않는다. 데몬이 그 절차를 지원하지 않으면 범용 지점(백업 전·후 명령)을 요청한다.
- 테스트: 실제와 같은 구조의 가짜 서버 폴더를 만들어 `backup_paths` 결과에 뺄 것이 없고 필요한 것이 다 있는지 본다. 실측 때 백업 zip 크기와 복원 뒤 접속·플레이어 데이터를 확인한다. `trial.py` backup 단계가 백업에 없는 플레이어 데이터를 경고한다(서버가 첫 시작 때 푸는 라이브러리도 잡힐 수 있으니 경로를 보고 판단한다).

## 정지: 플레이 데이터 안전

- 정상 종료는 게임이 저장하고 끝나는 공식 경로를 쓴다(공식 문서로 "종료 명령이 저장하는지" 확인). 저장하는 종료 명령 앞에 근거 없는 `save` + 고정 sleep을 넣지 않는다. 종료 명령이 저장하지 않는 게임이면 저장 명령 → 저장 완료 확인 → 종료 순서를 둔다. 데몬 경로(`stop_command`)와 모듈 `stop()`이 같은 절차여야 한다.
- `stop()`은 managed와 non-managed가 다르다(`docs/module-development-guide.md` §stop, `__example` 구현·테스트, 적합성 키트와 같은 계약).
  - **managed**(stdin이 없거나 REST로 정지하는 서버일 때 불림): 저장·종료 요청을 보낸 뒤 바로 `success: true`로 답한다. 서버가 아직 살아 있어도 요청이 접수됐으면 성공이다. 종료 대기와 강제 종료는 데몬이 맡는다. 모듈은 `wait_for_exit`·`force_kill`을 부르지 않는다.
  - **non-managed**(`managed: false`): 정상 종료 요청 → `wait_for_exit`(데몬이 준 `stop_timeout`) → 그래도 안 끝날 때만 `force_kill`. `force: true`이면 바로 강제 종료하되, 게임에 공식 강제 정지 API(예: REST `/stop`)가 있으면 먼저 쓴다.
  - 둘 다 정상 종료를 요청할 길이 하나도 없으면 죽이지 않고 `{"success": false, "error_code": "graceful_stop_unavailable", "message": <locales>}`로 답한다(사용자가 강제 종료를 고르면 데몬이 처리한다). 저장 요청이 실패했으면 삼키지 말고 응답에 싣는다.
- 데몬이 준 `pid`만 다루고 이름으로 프로세스를 찾지 않는다. 프로세스 확인·종료는 공용 `is_process_alive`·`wait_for_exit`·`force_kill`만 쓴다.

## 파괴 작업: 초기화·삭제

- 지우는 것은 **계산된 대상만**: 서버가 만드는 이름(월드, 설정·권한 파일, 로그·캐시, 실물 확인에서 본 회전 백업 이름 전부)을 목록으로 정하고 그것만 지운다. 회전 백업 하나라도 남기면 초기화 뒤에도 옛 월드가 폴더에 남는다. "허용 목록 밖은 전부 삭제"는 금지다. 설치 폴더는 사용자가 고르므로 바탕화면·문서 폴더일 수 있고, 인스턴스 폴더면 데몬 파일(`instance.json`, `backups/`, `logs/` 등)이 같이 있다.
- 지우기 전에 확인한다: 그 폴더가 서버 폴더인지(서버가 만든 흔적 파일이 있는지), 대상이 기준 폴더 **바로 아래 한 단계**인지(`abspath` 비교), 대상 이름이 빈 값·`.`·`..`·구분자·드라이브(`C:`)·끝 공백/점이 아닌지.
- 이 검증은 이름을 구하는 함수 한 곳에 둔다. 초기화에만 두면 같은 이름으로 경로를 만드는 백업·설정 쓰기·DB 확인이 구멍이 된다.
- 여러 인스턴스가 기본 데이터 폴더와 기본 이름을 함께 쓰는 구조(공용 홈 폴더로 되돌아가기)를 만들지 않는다. 그러면 한 인스턴스의 초기화가 다른 인스턴스의 월드를 지운다.
- `reset_server`가 무엇을 지우고 남기는지 `locales`의 `reset.description`에 정확히 적는다(GUI 초기화 화면이 보여 준다).
- 테스트: 서버 폴더에 사용자 파일·데몬 파일·다른 서버 폴더를 섞어 두고 초기화 뒤 그것들이 남는지, 빈 이름·`..`·절대 경로 이름에서 거절하는지, 서버 폴더가 아닌 곳에서 거절하는지 본다.

## 설치: 받은 것 고르기와 검증

- 배포물에 여러 OS 폴더가 있으면 **OS 폴더 이름으로** 고른다(`inspect_dist.py`가 OS 폴더를 보여 준다). 실행 파일 이름 일치·경로 길이·첫 항목으로 고르지 않는다. 고른 폴더가 없거나 둘 이상이면 실패한다. 다른 OS 폴더를 풀면 서버가 바로 죽는다(테라리아: Windows에 Linux용 Mono 파일을 풀었다).
- 기존 설정·월드를 덮지 않는다. 동봉 예시 설정은 없을 때만 푼다.
- 받은 파일 검증: 공식 체크섬이 있으면 받는 모든 바이너리에 쓴다. 없으면 HTTPS와 고정된 공식 호스트, 압축 무결성(CRC), 기대 실행 파일 존재로 확인하고, 조사 표에 "공식 체크섬 없음"과 근거 URL을 남긴다. 체크섬을 지어내거나 커뮤니티 해시를 쓰지 않는다.
- 테스트: 실제 배포물과 같은 구조(모든 OS 폴더)의 가짜 압축 파일로, OS마다 그 OS 파일만 풀리는지 본다.
