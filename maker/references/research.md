# 게임 조사 (공식 출처 + 웹 검색)

조사 결과를 `<game>/RESEARCH.md`(`new_module.py`가 만든 표, 또는 PR 본문)에 남긴다. 항목마다 출처 URL이나 실측 근거를 붙인다.
지난 점검 기록(버그 목록, 모듈 패턴 감사)이 있으면 같은 함수를 고치기 전에 열린 항목이 있는지 먼저 본다.

## 조사할 것

- 서버 실행 파일(런처가 아닌 실제 서버 exe/jar), 실행 인자 전체(공식 표기 그대로, 예: `-port=8211`이지 `--port`가 아님), 기본 포트(게임·쿼리·REST), 정상 종료 명령과 종료 때 저장하는지
- 명령 경로: 콘솔(stdin) / REST API / RCON 중 무엇을 지원하는지 (manifest.md §통신 경로 우선순위)
- **명령 전체 목록**: 공식 명령 문서와 서버 `help` 출력을 대조한다. 명령마다 정확한 이름(예: 좀보이드 추방은 `kickuser`), 인자, 권한, **서버 콘솔에서 쓸 때 필수인 인자**(플레이어가 없는 콘솔에서는 대상 이름이 필수인 명령이 있다), 되돌릴 수 있는지, 플레이어·월드에 주는 영향
- **공식 관리 API·이벤트**: REST, 관리 프로토콜, Query처럼 콘솔 출력 파싱보다 나은 길이 있는지(접속자 목록, 버전, 실제 적용 설정, 강제 정지)
- **설정 전체 목록**: 설정 파일 위치·형식(ini, properties, json, lua…)과 **그 형식의 문법**(이스케이프, 줄 이어짐, 따옴표, 목록 구분자, 인코딩), 키마다 형식·범위·기본값·의미, 재시작이 필요한지. 서버가 처음 만든 기본 설정 파일을 원본으로 삼는다. 세이브 쪽 파일이 설정을 덮는지(예: 월드별 옵션 파일)도 본다
- 세이브 구조: 월드·플레이어·권한(op·화이트리스트·밴) 파일 위치, 월드 위치를 바꾸는 설정·실행 인자(예: `level-name`, `--world-container`), 게임이 스스로 만드는 백업·캐시·로그 폴더(백업에서 뺄 것)
- **공식 백업 절차**: 쓰기 중지·즉시 기록 명령이 있는지(예: 마인크래프트 `save-off` → `save-all flush` → 복사 → `save-on`), 저장 명령이 끝날 때까지 기다리는 길
- 설치 방법: SteamCMD(app_id, 익명 여부, 베타) / 직접 내려받기(버전 목록 API와 **공식 체크섬**) / 수동. 공식 체크섬이 없으면 "없음"과 그 근거 URL을 적고 lifecycle.md §설치의 대체 검사를 쓴다
- **실행 전제(런타임)**: 서버가 배포물 밖에서 기대하는 것(XNA Framework, .NET, VC++ 재배포, Java 등). 실행 파일의 참조 목록이나 공식 문서로 찾고, 공식 재배포 파일의 주소·크기·서명·SHA-256과 서버가 실제로 쓰는 파일 목록(최소 집합을 실측)을 적는다. 테라리아 Windows 서버는 XNA Framework 4.0이 없으면 시작 즉시 `FileNotFoundException`으로 죽었고, XNA 4개·`XnaNative`·VC++ 2010 런타임 2개를 서버 폴더에 두니 떴다
- 정상 종료 로그 문구, 준비 완료 문구, 접속·퇴장 문구, 크래시 때 남는 파일, 약관(EULA), 접속자 수를 아는 길. **서버 언어 설정이 이 문구를 번역하는지**도 본다
- 서버가 인스턴스 폴더 밖에 쓰는 파일(사용자 문서·홈 폴더의 설정·즐겨찾기)과 스스로 만드는 회전 백업 이름(`.bak`, `.bak2` …)

## 실물 확인 (조사 단계에서 반드시)

제작 환경(클라우드 컨테이너 포함)에서 서버를 받을 수 있으면 아래를 직접 얻는다. 다른 OS용 빌드밖에 실행할 수 없어도 실행한다.
게임 코드가 같으면 명령·문구·저장 동작은 같고, 다른 것은 폴더 구조와 실행 전제뿐이다. 얻은 원문을 조사 표에 "실측"으로 남긴다.

1. **배포물 목록** (`maker/inspect_dist.py`). zip·tar는 항목 전체를 본다. 여러 OS 폴더가 들어 있는지, 같은 실행 파일 이름이 여러 폴더에 있는지 확인한다(테라리아 zip은 `Linux/`에도 `TerrariaServer.exe`가 있다). 커뮤니티 패키지 스크립트로 구조를 짐작하지 않는다.
2. **동봉 기본 파일의 원래 바이트** (`maker/inspect_dist.py`). 인코딩(UTF-8, BOM, cp1252 등), 줄바꿈, 주석 처리된 예시 키, 주석이 아닌 줄을 본다. 주석 처리된 예시 키도 설정 목록에 넣는다. 주석이 아닌 줄의 값이 기본값이다(테라리아 `priority=1`). 도구의 키 목록은 `키=값` 형식만 읽으므로, 다른 문법(json, lua, xml)은 파일을 직접 연다.
3. **실행** (`maker/probe_server.py`). 데몬과 같은 방식(stdin·stdout 파이프)으로 띄워 아래를 원문 바이트로 기록한다.
   - 준비 완료 줄, 정상 종료 명령 뒤의 줄, 저장 명령 출력과 걸린 시간
   - `help` 출력. 선언할 명령은 이 출력과 한 줄씩 대조하고, 문서에만 있는 명령은 실제로 보내(`--send`) "알 수 없는 명령"이 나오는지 본다
   - 콘솔 프롬프트가 줄바꿈 없이 찍혀 다음 줄 앞에 붙는지(테라리아 `: Server started`)
   - 파이프 stdin으로 보낸 명령에 답하는지. 답하지 않거나 출력이 끝날 때 몰려 나오면 `[launch] console = "pty"`로 의사 콘솔에서 다시 잰다(테라리아 Windows 서버는 파이프 입력을 읽지 않았다). 의사 콘솔에서는 줄 나눔이 달라질 수 있다
   - 서버 언어 설정이 있으면 언어마다 준비·종료 문구
   - 실행·저장 뒤에 생긴 파일 목록(월드 회전 백업, 인스턴스 밖 파일)
   - 서버 판이 바뀌면 문구도 바뀐다. 마인크래프트 26.x는 콘솔 명령 응답과 `stop`의 첫 줄을 `System chat: ` 뒤에 찍는다(`[Server thread/INFO]: System chat: Stopping the server`). 패턴은 지금 판의 원문으로 쓴다
4. 실행할 수 없는 항목(클라이언트가 있어야 하는 접속·퇴장·추방 등)은 비워 두고 "실측 못 함"으로 보고한다.
